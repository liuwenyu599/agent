## 开场 · 一句话定位

各位好，我汇报的是「云法智办」——一个**面向司法局政务办公、本地优先的 AI 助手平台**。
它把平时最耗人力的四件事——**写材料、查模板、做 PPT、核格式**——用一套 AI 能力串起来，
而且数据不出单位内网，符合政务合规要求。

（讲解提示：先抛定位，再抛"四个动作"，让听众立刻知道这东西是干嘛的。）

## 一、核心功能：平台能干什么

平台首页用四张功能卡概括主线，背后是一整套可扩展的模块：

**1. 智能写作（AI Writing）**
- 公文、汇报、总结等材料的 AI 生成；支持多智能体协作写作、风格适配、草稿变更审计。
- 亮点：生成不是"一次性黑箱"，而是可留痕、可回退、可多人公平排队。

**2. 模板中心（Templates）**
- 沉淀机关常用公文/材料模板，基于**配置驱动的通用 CRUD 引擎**。
- 亮点：新业务模块"只改配置就能接入"，不用为每个模块重写一套增删改查。

**3. PPT 助手（Slides）**
- 输入主题/文档，自动产出**可编辑**的 PowerPoint。
- 三种模式：自适应排版、严格克隆模板版式、以及我们的差异化能力——**设计稿构图模式**（在模板骨架内让模型重新构图，既保版式又保内容）。

**4. 格式校验（Compliance）**
- 按国标 GB/T 9704 对公文格式做**硬校验**：确定性规则 + 自动修正 + 大模型语义复核三层。
- 这是政务场景的"红线"功能，不可省、不可绕过。

**5. 支撑能力（后台三件套）**
- **知识库 + RAG 检索**：文档分块入库、向量检索，给写作/PPT 提供有据可依的素材。
- **工作流编排**：把"基础信息 → 起草 → 审核"这类流程固化成可执行的实例。
- **知识图谱**：支持 PNG / SVG / PDF 三种格式导出。

（讲解提示：功能不用逐个背参数，按"四张卡 + 三件套"讲，重点突出 PPT 和格式校验是差异化。）

## 三、技术难度：难点到底卡在哪

挑五个最硬的骨头，讲清"为什么难、我们怎么破"：

**① PPT 模板化生成（设计稿模式）—— 全平台最难的一块**
- 难点：让大模型"在模板既定骨架内重新构图"，既不能被模板绑死、又不能脱离版式乱画；
  还要处理几何越界审计、模型拒收回退、可视化诊断，且成品必须**二次可编辑**（换模板/配色/构图重生成）。
- 我们做了：分层引擎（page_authoring 构图重试、page_scene 场景约束、template_style 风格摘要、
  svg_layer 安全渲染、visual_primitives 视觉图元）+ 落地率/拒因探针。
- 价值：这是与通用"一句话生成 PPT"工具拉开差距的核心能力。

**② 并发与模型池隔离**
- 难点：本地只有有限算力（35B 单端点），PPT 批量生成和交互式写作会"抢"模型，写作饿死就直接卡 UI。
- 我们做了：进程内 FIFO 队列（并发上限 2）、跨线程共享模型池上限（4）、给交互式写作**预留请求名额**，
  收到 429 限频做 1/2/4 秒指数退避而非整页判失败。

**③ 公文格式校验（硬要求）**
- 难点：既要确定性规则零误判，又要能自动修正，还要用大模型补语义层；且这是不可删的合规红线。
- 我们做了：check_engine 规则引擎 + official_document_format（GB/T 9704）双层，确定性修复优先、语义复核兜底。

**④ RAG / 向量检索的工程对齐**
- 难点：FAISS 索引维度必须严格等于 embedding 维度（1024），bge-m3 多 provider（mock/http/auto）要兼容，
  且生产内网不能出网，embedding 服务要本地化部署。

**⑤ 合规部署链路（隐性难度）**
- 难点：生产内网严禁出网，代码只能"空气闸"式进场；镜像把代码烤进去、改宿主机不生效；
  默认 127.0.0.1 是容器 loopback 陷阱必须填宿主 LAN IP——这类坑不在功能里，但决定"能不能真用"。

（讲解提示：难度这节别念代码名，讲"现象—难点—我们的解法—价值"。
尤其强调 PPT 设计稿模式和并发隔离，是听众最容易记住的两点。）

## 四、收尾 · 三个亮点

1. **合规优先**：本地优先、数据不出域，适配国产算力（昇腾），契合政务信创要求。
2. **工程化交付**：近 4 万行双端代码 + 938 测试基线，不是一次性脚本。
3. **差异化能力**：PPT 设计稿构图 + 公文格式硬校验，是通用工具难以替代的两块。

（讲解提示：收尾回到"为什么值得做"——合规 + 可交付 + 有壁垒，三句话收。）

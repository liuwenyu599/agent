## 0. 背景与定位纠正

> 先前曾把「不够好」误读为「用不到、可删/停用」，这是错的。**格式校验是需要的**——司法局公文格式合规是硬要求，这道能力是必备项，不是可选项。真实情况是：**当前实现不够好、形态不合适，所以才没法真正投入使用**。
>
> 因此本方案的方向是「把它做够好」，而非移除。

## 2. 为什么「不够好、用不了」——真实短板

### 2.1 关键结构项完全不查（GB/T 9704 覆盖不全）

引擎只遍历 `doc.paragraphs`（`check_engine.py:304`），以下 GB/T 9704-2012 条款**全不检查**（audit §⑧-G8）：

| GB/T 9704 条款 | 内容 | 现状 |
|---|---|---|
| 7.3.2 主送机关 | 标题下空一行、左顶格、回行仍顶格 | **不检查** |
| 7.2.5 发文字号 | `发文机关代字〔2026〕N号`，上行文居左、下行文居中 | **不检查** |
| 7.2.5.2 签发人 | 上行文，与发文机关署名对称 | **不检查** |
| 7.3.4 附件说明 | 「附件：」开头、多个附件有序号 | **不检查** |
| 7.2.2 密级 / 7.2.3 紧急程度 | 版头左上角 | **不检查** |
| 7.5 页码 | 「- N -」、一字线、外侧 | **不检查** |
| 7.2.6 红色分隔线（版头红色反线） | 版头中红色反线 | **不检查**（红头属页眉/图片，引擎不遍历） |
| 7.4.2 抄送机关 | 印发机关和印发日期之上 | **不检查** |

→ 这些恰恰是公文**最易错、最该查**的。规则引擎「硬规则」查不了（需从文本语义判断位置/格式），AI 虽然能查，但——

### 2.2 AI 语义判断「只能看不能改」（不够好核心）

- `_ai_check` 返回的 issue **`fix_hint` 恒为 `None`**（`check_engine.py:742`），redesign §8-1 明确「本轮不实现 AI 类问题的自动修正」。
- 后果：主送机关位置错、附件说明格式不对、文号编排错——AI 能**发现**，但用户必须**手动**改；而改完之后 `recheck` 默认 `use_ai=false`（redesign §3.5），**又查不出来**语义项。
- → 查得到、改不了、查了也白查。这是「不够好」的本质。

### 2.3 形态割裂（不合适）

- 当前是「写完导出 → 去独立工作台上传校验」，与写作主流程割裂。
- 用户期望的是**写作时实时提示**（边写边标红），而不是事后另一页。

### 2.4 recheck 不带 AI

- 设计裁定 `use_ai=false`（旧 vLLM 8001 断，redesign §9-4）。即便恢复，语义级复检缺失仍让「应用→复检」闭环不完整。

### 2.5 可用性风险（需真机确认）

- redesign 声称「已实现」，但真机是否部署、桌面端 `FormatCheckScreen` 是否真三栏、35B 网关在写作侧是否可达，均需现场核实。若实际没跑通，「用不了」可能就是这一步。

## 3. 目标定义（「够好、能用」的标准）

| 目标 | 含义 |
|---|---|
| **G1** | 覆盖 GB/T 9704 主要结构项（主送/文号/签发人/附件/密级/紧急程度/页码/分隔线），不只是排版字号 |
| **G2** | AI 发现的语义问题**可定位、可一键修正**（至少给出可应用的 `replace_text` 动作），而非只建议 |
| **G3** | 写作时**实时**校验，边写边标红，不必事后上传 |
| **G4** | 复检能覆盖语义级（或明确标注「语义项需人工确认」） |
| **G5** | 真机可部署、桌面端接入、结果可信赖 |

## 4. 三大改进方向方案

### 方向 A：GB/T 9704 规则精化（最小改动，先做）

**在 `official_document_format.py:GBT_RULES` 扩充条款 + 在 `_content_rule_check` 增加「结构位置」检查（已有 `target="content"`，`check_engine.py:573`）。**

1. **可硬规则化的项**（引擎已支持自动修正）：
   - 附件说明格式：`^附件[:：]` 开头、多个附件用「附件：1. … 2. …」；命中加 `fix_hint` 纠正前缀。
   - 页码写法检测（若文本出现页码，核对「- N -」一字线格式）。
2. **需「文本语义 + 段落顺序」判断的项**（加进 `_content_rule_check`）：
   - 主送机关位置：检测标题之后、首个正文段落之前是否存在「××：」行；若不存在或位置错 → 报 issue（位置类，fix_hint 可给 `insert`/`replace` 建议）。
   - 发文字号格式：正则 `^[\u4e00-\u9fa5A-Z0-9]+〔\d{4}〕\d+号$` 校验（上行文/下行文位置不同，需结合文种判断）。
   - 附件说明位置：必须在正文之后、落款之前。
3. 这些项里**能安全自动改的**（附件前缀、页码一字线）给 `fix_hint`；位置类给建议 + 人工确认。

> 风险低、纯后端、不碰表结构，可独立部署验证。解决 **G1 大部分**。

### 方向 B：35B 语义级补强（突破 redesign §8-1 的「不做」，核心）

**改造 `_ai_check`（`check_engine.py:672`），让 35B 输出结构化、可修正的 issue。**

- 现有 prompt（`:700-710`）只要求输出 `location/element/current/expected/suggestion`，`fix_hint` 恒 `None`。
- **改造**：要求 35B 对「可安全自动修正」的问题额外输出 `fix_old` / `fix_new` 字段；解析后生成 `fix_hint={"type":"replace_text","old":fix_old,"new":fix_new}`。
- 关键：**引擎 `apply_fixes` 已支持 `replace_text`**（`check_engine.py:794-814`）→ 自动修正闭环直接打通，无需新修正能力。
- 覆盖：主送机关位置/格式、附件说明、文号编排、称谓前后不一致、时间表述——这些 AI 能给出具体改写。
- 对无法安全自动改的（密级判断、红色分隔线）保持 `fix_hint=null` 仅建议。
- **recheck 放开 `use_ai=true`**：当 35B 可达时复检带语义；不可达时降级并在响应标注 `skipped_reason`（复用 redesign 的 `skipped_reason` 机制）。

> 解决 **G2、部分 G4**。需 35B 写作侧网关稳定。

### 方向 C：实时嵌入写作流程（解决形态割裂，最大改动）

**把校验从「上传式工作台」前置到写作编辑器内。**

1. **后端**：在写作服务的「保存草稿 / 流式生成结束」节点，对当前文档跑 `check_engine.check_file`（轻量，确定性规则毫秒级；AI 部分异步）。
   - 新增 `POST /writing-tasks/{id}/format-snapshot` 或在现有草稿保存链里内联，返回 issue 列表。
   - 复用 `extract_paragraph_properties` 给编辑器标红用。
2. **桌面端**：`WritingScreen.kt` 编辑器对命中段落标红 + 侧栏问题列表 + 点击定位；支持「一键应用全部规则类修正」。
3. **与现有工作台并存**：实时校验是「轻量提示」（写作中），独立工作台是「深度审校 + 修正稿导出」（事后）。三栏对比 UI（redesign）可复用为实时校验的「详情抽屉」。
4. **性能**：确定性规则对 <1MB docx 毫秒级；AI 校验异步 + 缓存，不阻塞输入。

> 解决 **G3**。改动面最大（编辑器 + 写作服务 + UI），需独立 UI 设计，放最后阶段。

## 7. 验收标准（对应 G1–G5）

- **G1**：用一份真实含主送/文号/附件的公文，校验能报出主送位置异常、文号格式错、附件说明错位，且不误报正常公文。
- **G2**：AI 发现的「称谓不一致」「时间表述」等问题，点「应用」后能真实改写文档（python-docx 打开断言文本已变），且应用前展示 diff 供人工确认。
- **G3**：写作时在编辑器内即看到格式问题标红，无需导出上传。
- **G4**：`recheck` 在 35B 可达时复检语义项；不可达时响应带 `skipped_reason` 且语义项明确标注「需人工确认」。
- **G5**：真机部署后，桌面端入口可用、结果可信。

---

## 8. 风险与取舍

1. **AI 自动修正可能改错**（replace_text 跨 run 误命中）→ 必须「应用前预览 diff + 人工确认」一步，绝不直接静默改写。
2. **实时校验的 AI 部分延迟** → 异步执行 + 结果缓存，不阻塞输入；确定性规则同步跑。
3. **35B 不可用降级** → 实时校验退化为仅确定性规则；独立工作台语义项标注「需人工确认」。
4. **红色分隔线 / 红头 / 表格 / 页码位置**：属页眉/页脚/图片/表格，引擎不遍历，阶段 1–3 均不覆盖，列为后续（若要需引入 docx 页眉/表格遍历，属引擎级扩展，不在本方案）。

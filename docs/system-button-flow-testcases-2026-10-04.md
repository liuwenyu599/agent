# 云法智办 — 系统级按钮与流程测试用例集

## 1. 基本信息

- **项目名称**：云法智办 / 白云司法局智慧办公平台
- **覆盖范围**：后端 REST 接口 159 条（实时导出，非仓库里的 openapi.json）、桌面端 15 个功能屏
- **测试类型**：功能测试 + 接口契约测试 + UI 流程测试 + 边界值测试
- **设计日期**：2026-10-04
- **被测版本**：`2f225b3`（分支 `app`）

### 1.1 本次检查是怎么做的

不是照着需求文档拍脑袋写用例，而是先把系统的真实边界量出来：

| 手段 | 说明 |
|------|------|
| 实时路由导出 | 从运行中的 FastAPI 应用导出 OpenAPI，**不用**仓库里那份（已过期，见 F-2） |
| 测试覆盖交叉比对 | 把 `server/tests/*.py` 的 URL 调用（含 `f"{BASE}/xxx"` 拼串，先还原再比）去匹配 159 条路由 |
| 桌面端按钮枚举 | 正则提取 15 个 `*Screen.kt` 里的按钮文案与导航目标 |
| 实测探测 | `TestClient` 逐个访问，用真实状态码判断可达性，而不是只读代码 |

> 局限说明：覆盖比对是**字符串级**的，会有假阳性与假阴性。凡是判定为「未覆盖」的关键项，都再用 `grep -rl` 抽验过一遍，下文标注的未覆盖模块是抽验后确认的。

### 2.2 业务规则

| 规则ID | 规则描述 | 对应模块 |
|--------|----------|----------|
| BR-01 | 知识库可见性三段式：列表与详情必须同口径，不得出现「列表看得见、详情打不开」的半泄漏 | 知识库 |
| BR-02 | 写作 `_finalize_draft` 为整篇重写，旧正文必须归档为 v{n+1}，不得就地覆盖 | 写作台 |
| BR-03 | `revise()` 必须先 `merge_context` + `compute_missing` 再 `_postprocess`，否则出现「改了日期正文没改」 | 写作台 |
| BR-04 | 训练相关 REST 在本部署（推理卡）下不注册，属**有意设计**，不得当成缺陷修回去 | 训练 |
| BR-05 | PPT 生成必须走异步 job（`POST /jobs` + 轮询 `/status`），不得同步阻塞超过网关超时 | PPT |
| BR-06 | 遇到 pptx/png 等二进制文件名，检索与比对时必须 `grep -a`，否则报 `binary file matches` | 全模块 |
| BR-07 | 采集链路若未配置 `SFT_SNAPSHOT_DIR`，则全部空操作，不得产生任何副作用 | 写作台/采集 |

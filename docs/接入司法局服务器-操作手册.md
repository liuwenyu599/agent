# 接入司法局服务器 · 操作手册（已实测 · 2026-09-22）

> 目标机器：`10.128.85.133`（root，SSH 22）
> 实测结论：**后端 + 4 个 vLLM 模型 + PPTAgent 全在同一台机器上**，本机到全部端口直连可达，**不需要 SSH 隧道**。

## 0. 实测端口与模型身份（已逐个探测确认）

| 端口 | 服务 | 模型 / 说明 | max_model_len |
|---|---|---|---|
| `8000` | **本平台后端** | `/health` → `{"status":"ok","version":"1.0.0"}`；`/docs` → 200；受保护接口 → 401 | — |
| `8001` | vLLM | `Qwen2.5-VL-3B-Instruct`（小视觉，备用） | 16384 |
| `8002` | vLLM | **`Qwen2.5-VL-7B-Instruct`（视觉，推荐）** | 8192 |
| `8003` | vLLM | **`Qwen2.5-14B-Instruct`（主文本）** | 8192 |
| `8004` | vLLM | **`DeepPresenter-9B`（PPT 专用，32k）** | 32768 |
| `7861` | **PPTAgent / DeepPresenter**（Gradio 5） | `/gradio_api/info` 里有 `/send_message`，**6 入参 / 5 出参**，与后端契约完全一致 | — |
| `22` | SSH | 仅密码登录（publickey 被拒） | — |

## 1. 桌面端 baseURL（已改好）

文件：`%APPDATA%\JudicialAIDesktop\server.json`

```json
{ "baseUrl": "http://10.128.85.133:8000" }
```

改完**必须重启桌面端**（配置是启动时读入 `AppState.serverConfig` 的）。也可以在桌面端「设置」页的地址框里直接改，最终写的也是这个文件。

⚠️ 两个坑：
- **不要带路径前缀**：`/api/v1` 会拼在 `baseUrl` 后面，写成 `http://ip:8000/api/v1` 会拼出重复前缀。
- 必须是纯 `http://host:port`：PPT 逐页预览图的 URL 是拼在 **origin** 后面的（`PptJobState.kt`）。

## 2. 服务端 `.env`（关键，需要你手动执行）

⚠️ **SSH 只能密码登录，自动化脚本跑不了**（`Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password)`，且本机没有 `sshpass`/`plink`）。下面这段需要你自己登上去执行。

### 2.1 直接用现成文件（推荐）

仓库里已备好：`deploy/justice-server.env`

```bash
# 本机（Git Bash）
cd /d/Projects/judicial_app
scp deploy/justice-server.env root@10.128.85.133:/tmp/justice-server.env

# 服务器上（会提示输入密码）
ssh root@10.128.85.133
cp /tmp/justice-server.env /opt/judicial-ai/server/.env      # 路径按实际部署目录改
# 找到 PPTAgent 产物目录后补一行（只影响逐页预览，不影响生成）：
#   echo 'PPT_AGENT_WORKSPACE_DIR=/实际/产物/目录' >> /opt/judicial-server/.env
```

### 2.2 或者直接粘贴

```env
MODEL_SERVICE_URL=http://127.0.0.1:8003/v1
MODEL_NAME=Qwen2.5-14B-Instruct
MODEL_API_KEY=
MODEL_TIMEOUT=300
MODEL_CTX_LIMIT=8192
MODEL_TEMPERATURE=0.4
MODEL_MAX_TOKENS=4096

VISION_MODEL_URL=http://127.0.0.1:8002/v1
VISION_MODEL_NAME=Qwen2.5-VL-7B-Instruct

PPT_MODEL_URL=http://127.0.0.1:8004/v1
PPT_MODEL_NAME=DeepPresenter-9B

PPT_AGENT_URL=http://127.0.0.1:7861
PPT_AGENT_SUBMIT_PATH=/gradio_api/call/send_message
PPT_AGENT_TOTAL_TIMEOUT=1800

OCR_ENABLED=false
```

> 后端和模型同机，所以用 `127.0.0.1` 回环（最快，不依赖外部 IP 绑定）。若回环不通，把 `127.0.0.1` 换成 `10.128.85.133` 即可（vLLM 绑的是 `0.0.0.0`，实测两种都通）。

### 2.3 三个容易踩的点

| 项 | 坑 |
|---|---|
| `MODEL_CTX_LIMIT` | 8003 的 `max_model_len` 只有 **8192**，沿用原来的 16384 长 prompt 会被 vLLM 直接拒；已改成 8192 |
| `PPT_AGENT_SUBMIT_PATH` | **必须显式写** `/gradio_api/call/send_message`。`config.py` 的默认值 `/api/ppt/generate` 是旧契约残留，不覆盖会 404 |
| `VISION_MODEL_URL` | 配上之后图片识别走 VL 模型（8002），**不再需要 OCR**，所以 `OCR_ENABLED=false` 无所谓了 |
| `PPT_AGENT_WORKSPACE_DIR` | 只影响逐页预览。服务器上找真实产物目录：`find / -maxdepth 6 -type d \( -name workspace -o -name outputs \) 2>/dev/null \| grep -iE "ppt\|deep\|present"`；Docker 部署则用 `docker inspect <容器> --format '{{json .Mounts}}'` |
| `SECRET_KEY` | 生产环境务必重新生成：`openssl rand -hex 32` |

## 3. 本机 `.env`（已改好）

`server/.env` 已整体切到司法局服务器（供本机跑后端、连远端模型的场景）：

## 5. 验证顺序

1. `curl http://10.128.85.133:8000/health` → ok
2. 桌面端重启 → 能登录即通
3. 传一张图片到写作台识别 → 应走 8002 的 VL 模型（不再报「OCR 未启用」）
4. 生成一次 PPT → 查库确认真的走了 PPTAgent：

```bash
cd /opt/judicial-ai/server
python -c "
import sqlite3
c=sqlite3.connect('data/judicial_app.db')
for r in c.execute('select title,job_renderer,job_error from ppt_documents order by updated_at desc limit 3'):
    print(r)
"
```

- `job_renderer = pptagent` ✅ 真的（会有表格/图表）
- `job_renderer = local` ❌ 回退了，`job_error` 里是回退原因（本机此前就是 `PPTAgentError: 健康探测未通过`，因为 SSH 隧道断了）

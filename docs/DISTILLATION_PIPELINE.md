# 外部强模型公文蒸馏流程

本流程对应 backlog 第 16 项。目标是把外部强模型用于**离线数据生产**，再将通过质量闸的样本用于本平台 few-shot 或 LoRA；生产服务本身不连接外部模型。

## 1. 外部生成

在获准的外部环境中选择能力更强的模型，按真实业务分布构造不同文种任务。每条输出必须保留来源模型与上游追踪 ID：

```json
{"instruction":"起草……","input":"可选材料","output":"完整正文","document_type":"通知","source_model":"strong-model-name","source_id":"batch-001-0001"}
```

生成侧要求：

- 只使用脱敏或可公开材料，不把生产知识库、个人信息、内部文号等秘密数据发送给外部服务；
- 输出必须是完整成文，不接受提纲、占位符或“待补充”；
- 文种必须显式标注，不由导入脚本猜测；
- 同一任务可由多个模型生成，但必须保留 `source_model`，便于后续按模型做质量对比。

## 2. 进入内网前质检

将外部 JSONL 带回受控环境后执行：

```bash
cd server
python -m scripts.prepare_distillation_dataset \
  /secure/import/external_official_docs.jsonl \
  /secure/training/distilled_v1
```

脚本会确定性完成：

1. schema / 来源模型校验；
2. 过短、占位、明显循环退化样本剔除；
3. 正文 SHA-256 去重；
4. 稳定 train/val 切分；
5. 按文种生成 bounded few-shot 集；
6. 输出 `report.json`，记录拒绝原因、文种分布和来源模型分布。

任何被拒绝的样本都不会被自动“修好”后混回训练集。需要修订时，应回到外部生成/人工审核阶段产生新的可追踪样本。

## 3. 产物用途

- `fewshot.jsonl`：候选范文池。进入知识库前仍需人工审核，并保留“仅学风格、不迁移事实”的现有风格卡抽取链路。
- `train.jsonl`：LoRA/SFT 候选训练集。训练前继续执行现有训练模块的人工审核/状态流转。
- `val.jsonl`：固定验证集，不得与训练集互换，避免用验证样本反复调参造成数据泄漏。
- `report.json`：每批数据的审计依据，应和原始 JSONL、模型版本、生成参数一起归档。

## 4. 上线判定

蒸馏不是“样本越多越好”。至少比较同一固定验证集上的：格式硬伤率、QualityGate D 率、人工修改距离、事实错误率和重复退化率。只有相较当前生产基线有稳定改善，才允许把新 few-shot/LoRA 切入生产；否则保留现有模型与风格卡链路。

## 二、上线阻断项（必须修）

### P0-1　`/uploads` 静态目录零鉴权 —— 司法文书原件可被任意下载

- 位置：`server/app/main.py:138`
  ```python
  app.mount("/uploads", StaticFiles(directory=str(uploads_dir)), name="uploads")
  ```
- 落盘位置：`application/chat/attachment_service.py:52` → `uploads/chat/{user_id}/{uuid}.docx`
- **这是真实泄露面，不是理论风险**。文件名是 UUID 不可猜，但 URL 会经前端 Referer、聊天记录、代理日志外泄。任何拿到 URL 的人**无需 Token 即可下载**任意用户上传的司法文书原件。

**修法**：删除 mount，改为 `/api/v1/files/{id}` 路由，走 `get_current_user` + 校验归属。兼容期可保留旧路径但加随机前缀 + 短 TTL。

### P0-2　登录接口零限流 —— 可无限爆破

- 位置：`interfaces/auth.py:24` → `application/identity/service.py:74` 直接查库比对
- 全仓 `grep ratelimit|slowapi|限流` = **0 命中**
- 政务内网横向可达，办公终端共用网络，密码复杂度规则再严也挡不住爆破

**修法**：`/auth/login` 加 IP + 用户名双维度限流（5 次/10 分钟，锁定 15 分钟）。单机部署用内存缓存即可，无需引 Redis。

### P0-3　`/auth/register-first` 可被抢注 —— 部署到管理员建号之间的窗口即失守

- 位置：`interfaces/auth.py:55`（注册）+ `:64`（匿名探测是否首用户）
- 仅靠 `count()==0` 判定，无一次性令牌

**修法**：改为部署时命令行 `python -m scripts.create_admin` 引导建号，删除该 HTTP 端点。这一项**部署前必须闭环**，否则等于没有认证系统。

### P0-4　幻觉抑制被提示词反向覆盖 —— 等于官方鼓励模型编造法条

这是本次审计**最值得警惕**的一项。

- `application/shared/writing_assistant.py:95`：
  > "确实全部不相关时才说未找到，**再用你自己的知识回答**"
- `writing_assistant.py:46`：
  > "**不得因信息不足而拒绝回答**"

这两句与公文的可追责要求根本冲突。给法官/检察官写公文，产出"看似合规、实则无法追责的虚假引用"，比拒答严重得多。

配套问题：
- **无 rerank**：全仓无 cross-encoder，召回 top_k=3 直接喂 LLM
- **阈值偏松**：`RAG_SCORE_THRESHOLD=0.5`，bge 系列归一化内积下无关文档常在 0.3~0.6，0.5 拦不住
- **检索为空不拒答**：`application/chat/service.py:174-194` 拿空 sources 继续喂模型
- **换模型静默丢数据**：`EMBED_MODEL_PATH` 默认是 bge-small-zh-v1.5（512维），但生产目录是 bge-m3（1024维），`vector_store.py:76-81` 只 warn 不报错

**修法（按优先级）**：① 删掉 `:95` 的自由生成兜底，改真拒答；② 阈值提到 0.7 并用真实评测集标定；③ 接 `bge-reranker-v2-m3`，召回 30 → 重排 3；④ 换 embedding 模型必须同步重建索引，加启动校验。

### P0-5　安装包比源码旧 3 天 —— 当前包缺登录页窗口按钮修复

实测时间戳：

| 对象 | 时间 |
|------|------|
| `build/installer/云法智办-安装程序-1.0.0.exe` | 2026-09-30 17:19 |
| `features/auth/LoginScreen.kt` | **2026-10-03 14:13** |
| `design/layout/AppShell.kt` | **2026-10-03 14:13** |

最新提交 `9a0ee9f`"登录页补上无边框窗口的最小化/最大化/关闭按钮"改的正是这两个文件。当前包里登录窗**关不掉、不能最小化**，用户只能杀进程。

**修法**：`cd desktop && .\installer\build-installer.ps1 -SkipBuild`（约几十秒）。注意需先跑 `gradlew createDistributable`（要 JDK 17），因为 app 产物（09-30 15:47）也是旧的。

### P0-6　`.ofd` 声明支持但未实现 —— 政务版式文件直接报错

- `core/config.py:224` 把 `.ofd` 列进 `SUPPORTED_DOC_TYPES`（UI 上用户能选）
- 全仓 grep `ofd` **仅此一处命中**，解析器无分支 → 落到"暂不支持" 400

OFD 是政务公文常见格式，写在支持列表里却不能用，用户会直接报障。

**修法**：要么实现 OFD 解析（OFD 是 ZIP+XML，可直接解包抽文本），要么从 `SUPPORTED_DOC_TYPES` 移除并在前端置灰。**不要留一个假的"支持"。**

## 四、已确认安全的部分（不需动）

审计确认以下方面做得正确，可直接作为交付亮点：

- **知识库越权防护**：`application/knowledge/access.py:107-171` 权限矩阵完整，科室强隔离；所有读接口走 `get_document_checked`（`service.py:209-216`）
- **文档越权防护**：`interfaces/documents.py:55/65/76/86/95` 全部透传 `user.id` 到 service，**改 URL 里的 id 无法越权**
- **审批流权限**：`service.py:253-268` `_can_view`/`_can_act` 按权限码判定
- **SQL 注入**：业务代码全 ORM 参数化，无字符串拼 SQL
- **代码执行**：`eval`/`exec`/`pickle.loads`/`yaml.load`（非 safe_load）**0 命中**；subprocess 均列表参数、无 `shell=True`
- **密码存储**：bcrypt cost=12（符合 OWASP）；审计日志**不记密码**
- **客户端凭据**：token **只在内存不落盘**（`ApiClient.kt:49-53`），密码不缓存，日志有红线注释并落实
- **PPT 长任务**：客户端 20 分钟超时 + 30 分钟轮询上限 + 退避，全局状态保住切页不丢任务（`PptJobState.kt:168-174`）——这是全项目做得最好的部分
- **检索工程**：混合 RRF（向量+关键词）+ 结构优先分块 + 邻近块扩展 + 每条结果带 `source` 溯源

## 五、运维缺口

| 项 | 现状 | 风险 |
|----|------|------|
| **数据库定期备份** | 无定时任务，只有部署前手工备份 | **数据丢失不可恢复 = 不可投产** |
| 向量索引备份 | 未纳入备份范围 | 重建成本高 |
| 监控告警 | 无 Prometheus/日志采集 | 服务挂了要靠人肉发现 |
| 扫描件 OCR | `OCR_ENABLED=false` 且**知识库链路无 OCR** | 纸质公文扫描件入库会直接报错 |
| 客户端版本可见性 | 无 | 出问题无法定位用户版本 |

## 六、建议的落地路径

先上 P0-1 ~ P0-3 + P0-5，限定科室范围，**明确告知使用者"AI 产出需人工复核"**。

补 P0-4（幻觉抑制）+ P0-6（OFD）+ 上线前应修项 1~5。
建评测集：50~100 道真实公文题，量化 faithfulness / context precision，**有基线才敢推广**。

### 阶段 C：能力补齐（并行推进）
OFD 解析、知识库 OCR、bge-reranker、审批模块桌面端入口、客户端自动更新（内网做版本检查接口）。

**修复方案**（三选一或组合）：

## 🔴 #2 模板格式完全不生效

| 项 | 内容 |
|----|------|
| **现象** | 选模板后第一行直接是正文，没有红头、发文字号、主送机关、落款单位，正文也不分条 |
| **实际根因** | 模板数据结构里**根本没有格式字段**，且 prompt 明确禁止模型输出这些 |

**证据链**：

1. **模板是"描述文字"不是"格式骨架"** ✅ 已验证
   ```python

   23 个模板全是这类自然语言描述，`grep structure` 在内置模板中**零命中**。

2. **数据库无格式字段** ✅ 已验证
   `models/templates.py:15-50` 只有 `need_red_header` / `need_signature` / `need_date` / `need_doc_number` 四个**布尔开关**，无字号、字体、行距、缩进。

3. **prompt 明确禁止模型输出** ✅ 已验证（这就是"第一行就是正文"的直接原因）

   "标题、主送机关由系统结构化字段单独排版；你的输出正文不要重复标题或主送机关，从正文第一段直接开始"
   ```
   配套 `_clean_markdown`（:1211-1221）还会**主动剥离 `**加粗**` 和 `#`**。

4. **发文字号/落款在模板布尔位里是 True，但只在导出时才用**

**⚠️ 关键发现（最高性价比修复点）**

> **系统"会检查格式、会修正格式，但不生成格式"——两条链路完全隔离。**

`server/app/application/system/seed_v3.py:94-169 GBT_RULES` 已有完整标准格式定义：
- 页边距 3.7 / 3.5 / 2.8 / 2.6 cm

但 `grep format_check` 在 `writing/` 模块**零引用**。

**修复方案**：
- **P0-a（性价比最高）**：把 `GBT_RULES` 抽成共享常量，`docx_export.py` 按段型（title / body / heading1 / heading2 / signature / date）套格式。**不改模板、不改数据库、不动模型**，格式问题当场消失

- **P1**：`prompts/write/notification.jinja2:11-15` 里躺着完整的 GB/T 9704 字体字号要求，**但全文无人调用**（`_render_prompt` 只渲染 `search/legal_query`），需并入写作台系统提示词

## 🔴 #3 对话修改过于死板

| 项 | 内容 |
|----|------|
| **现象** | 用户说"在补贴标准那节加一句话"，系统回复"无法把'补贴标准'唯一定位到当前正文……" |

2. **回复是硬编码的元信息** ✅（"宛若智障"的直接来源）
   ```python

   reply = f"已只修改定位到的目标片段并保存为 v{version}，未让模型重生成其余正文。"
   reply += "\n\n本次实际变化：\n" + summary
   ```
   模型对回复措辞**零参与**。

3. **还有更笨的一行** ✅
   ```python
   // task_service.py:642 / ops_task_service.py:247 / semantic_task_service.py:324
   reply = it.get("reply") or "已理解。"
   ```
   意图识别失败就回三个字。

4. **意图识别是纯子串匹配，两套并存互不调用** ✅
   `writing_assistant.py:197-207` `_detect_intent` 顺序 `search→writing→summary→rewrite→chat`，纯子串匹配。"把第二部分写**详细**一点"含"写"字 → 直接套**整篇公文**的硬性要求。

5. **无记忆** ✅

**修复方案**：
- **P0**：ops 增 `append_to_section` / `insert_paragraph` / `delete_range` 三类操作
- **P0**：硬编码 reply 改自然语言首句（diff 降为次要折叠信息）
- **P0**：`or "已理解。"` 改为让模型做一次纯问答兜底
- **P1**：`_detect_intent` 换成复用 `is_writing_request`
- **P1**：`/chat/send` 加 SSE + 前端打字机（见 #15）
- **P1**：`_RESPONSE_CONTRACT` 第⑤⑦条松绑（"直接执行不要确认" → "先回一句你理解到什么，缺什么问一句"）。**保留③④⑨可追责底线不动**

## 🟢 #10 全局 Toast 通知（本次新增需求）

**现状**：11 个页面各写各的状态提示条，切换页面即失效、互相干扰。

```kotlin
// 提示条散落位置（已 grep 确认）
features/admin/AdminScreen.kt:131            vm.status?.let { ... }

features/writing/WritingScreen.kt:1425       WritingStatusLine(vm.status)
```

**技术方案**：

| 项 | 方案 | 依据 |
|----|------|------|
| 全局单例 | `object ToastState`，用 `mutableStateListOf<ToastItem>` | 与 `AppState`（`app/AppState.kt:39`）现有模式一致 |
| 挂载点 | `AppShell.kt:99` 的 `Box(Modifier.fillMaxSize())` 内叠放 | 该 Box 已包住整个内容区，不影响页面布局 |
| 每条模型 | `id / message / type(INFO,SUCCESS,ERROR,WARNING) / createdAt` | — |
| 自动消失 | `LaunchedEffect(item.id) { delay(4000); 淡出 }` | — |
| 悬停暂停 | `var hovering by remember { mutableStateOf(false) }`，暂停倒计时 | — |
| 点击展开 | 默认 `maxLines = 2` + `overflow = Ellipsis`，点击切换 `maxLines = Int.MAX_VALUE` | — |
| 堆叠 | `Column` 垂直排列，最新在上，限制最多显示 4 条 | — |
| 调用方式 | `ToastState.show("已保存 v3", SUCCESS)`，任何 Composable/ViewModel 都能调 | 全局对象，无需传参 |

**⚠️ 挂载点的重要约束（已验证）**：

```kotlin
// app/App.kt:27-31
AppTheme {
    if (!AppState.loggedIn) {
        LoginScreen()
        return@AppTheme        // ← 登录页直接 return，绕过 AppShell
    }
    ...
    AppShell(...)              // ← AppShell 只在已登录时出现
}
```

登录页**不走 AppShell**。所以：
- 若只挂在 `AppShell.kt:99`，**登录页的提示（如"服务器不可达""地址未配置"）无法用 Toast**，仍需页面内提示条
- **建议**：在 `AppTheme` 内、`if` 判断**之外**再套一层 `Box`，把 `ToastHost` 放在这里 → 登录页与主界面都能收到通知
- 多开窗口注意：`AppState` 是全局 object，`WindowSession` 是每窗口本地。**Toast 需确认是全局共享一条队列还是每窗口独立**——建议每窗口独立（与 `WindowSession` 一致），否则 A 窗口的操作提示会飘到 B 窗口

**改造范围**：新增 `design/components/ToastHost.kt`，在 `App.kt` 的 `AppTheme` 内挂载；各页面提示条**先不动**（避免一次性大改引入回归），新功能先用于新增通知，逐步迁移旧的。

**注意**：`WritingStatusLine`（`WritingScreen.kt:1425`）已经做过语义分流（失败红框 / 成功浅蓝条），注释里写了"之前用户每切一次页面就被红字迎面打一次"——说明**页面内提示条的历史体验问题已被记录过**，全局 Toast 正好解决这类问题。

## 🟡 #15 搜索栏高度与顶栏一致（视觉缺陷）

| 项 | 内容 |
|----|------|
| **现象** | 搜索栏高度和顶栏一样高，很丑 |

**已验证根因**：
```kotlin
// design/components/AppControls.kt:297 AppSearchField
Row(modifier.heightIn(min = Dimens.hControl) ...)   // ← 只有 min，没有 max
    androidx.compose.material.TextField(...)          // ← M3 默认最小高度 56dp
```

**修复方案**：
```kotlin

```

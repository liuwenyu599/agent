## 二、缺陷清单（B1–B12）

### P0

**B1 · 科室管理员操作成功后，成功提示会被越权 403 顶掉** —— 这是「点了没反应 / 点了报错」的主因之一

`AdminViewModel.act()` 成功后无条件 `loadAll()`，而 `loadAll()` 里的 `/knowledge/stats` 与 `/users/` 都是 `require_developer`。科室管理员点「通过」的实际时序是：

1. `POST /knowledge/review` → 200，文档状态已改成 published（**服务端真的成功了**）
2. `status = "审核完成"`
3. `loadAll()` 并发打出两条 403 → `status = "System admin required"`

用户看到的就是「我点了通过，它给我报错」。

修复：`act()` 改为按 `systemAdmin` 收窄刷新范围（非系统管理员只刷知识库与文档），并把成功提示放在刷新**之后**写；刷新失败时合并成「已通过（列表刷新失败：…）」，不再互相覆盖。同时加了 `busy` 锁，防止连点重复提交。

**B2 · 科室管理员根本没有管理后台入口**

服务端 `/knowledge/pending` 是 `require_knowledge_admin`、`/knowledge/review` 走 `assert_can_review`，**明确授权科室管理员审核本科室文档**。但桌面端导航里 `adminItems` 只在 `AppState.isDeveloper` 时挂载，科室管理员看不到任何入口 → 本科室上传的文档会永远卡在「待审核」，只有系统管理员能放行。

修复：`knowledgeAdminItems` 增加「文档审核」导航项（`adminTab = 3`），developer 与 knowledge_admin 都能直达。

**B12 · 桌面端 HEAD 编译不过**（见第一节）

### P1

**B3 · 「确认驳回」按钮是灰的，点了没反应，也不说为什么**

驳回弹窗用 `enabled = !rejected || comment.isNotBlank()` 静默禁用：意见一栏一空，按钮就点不动，界面上没有任何必填提示。这是最典型的一处「点击无反应」。

修复：改成**点击时校验**，空意见点下去直接弹内联错误「请写明驳回原因，否则无法提交」。重置密码弹窗同样处理（原本 `enabled = pwd.length >= 6` 静默禁用）。

**B4 · 「待审核」页「上传者」「时间」两列恒为空白**

`/knowledge/pending` 下发的是 `uploaded_by` / `uploaded_at`，而 `/knowledge/documents` 下发的是 `uploader_name` / `created_at`。DocsTab 三个子页共用一张表、读的是同一批列名，于是只有「待审核」页这两列是空的，另外两页正常。

修复：`list_pending` 改用与 `/knowledge/documents` 同一个 `_display_dict` 输出，保留 `uploaded_by` / `uploaded_at` 做兼容。

**B5 · 驳回是单行道**

服务端 `review_document` 并不校验前态，`rejected → approved` 完全可行；但界面「已驳回」子页没有任何操作按钮，误驳回的文档永远回不来。

修复：「已驳回」子页增加「重新通过」。

**B6 · 归档等于数据消失**

归档后 status 变成 `archived`，而三个子页分别是 pending / published / rejected，一个都不含它；服务端也没有反向接口。归档一次，文档在管理后台彻底消失且无从找回。

修复：新增 `POST /knowledge/documents/{doc_id}/unarchive`（状态回到 published，并调用 `retry_index` 补回被物理删除的向量索引——否则文档显示「已发布」却检索不到）；界面新增「已归档」子页 + 「恢复发布」。

### P2

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| B7 | 知识库只能删不能建 | `AdminRepository.createKb` 已接好，界面没入口（死代码） | KbTab 增加「＋ 新建知识库」（名称 / 说明 / 可见范围） |

## 二、发现并修复的缺陷

### D1（P0）复检之后，已应用的修改全部丢失

- 现象：应用若干条修改 → 点「重新校验」→ 文档退回原文，此时再点「导出修正稿」导出的是**未修改的原始文件**。
- 根因：当前稿不是落盘文件，而是「原始文件 + `applied_ids`」实时重放出来的；`recheck()` 结尾把 `applied_ids` 重置为 `[]`，重放时就没有修正可放了。复检只确认了「修改生效」，却把修改本身丢掉了。
- 修复：`recheck()` 改为 `applied_ids = 已应用的 ∪ 已复检确认的` 并写清语义——`applied_ids` = 已写入当前稿的修正，`resolved_ids` = 复检确认生效的修正。
- 护栏：`test_recheck_keeps_applied_fixes`、`test_export_keeps_fixes_after_recheck`。

### D2（P1）新建的规则默认不生效

- 现象：管理员在「规则管理」新建规则、界面提示「规则已保存」，但下次校验完全不检查这条规则（表现为"配了没用"）。
- 根因：`list_for_check()` 在不指定规则时只取 `is_default == true` 的规则；而桌面端新建规则时「默认规则」复选框默认**未勾选**（`RuleForm.isDefault = false`），复制出来的规则更是硬编码 `false`。
- 修复：不指定规则时取**全部启用规则**；`is_default` 只保留"预置/默认勾选"语义，不再当生效开关。同时把新建表单默认改为勾选、复制规则改为继承原值。
- 护栏：`test_custom_rule_participates_in_check`（刻意用 `is_default=false` 复现桌面端行为）。

### D3（P1）可以保存一条"空规则"

- 现象：校验项为空（或全是引擎不认识的键）也能保存成功，之后这条规则永远查不出问题，用户无法区分"规则没生效"还是"文档本来就合规"。
- 修复：`create_rule / update_rule` 走与 AI 编译同一道白名单过滤，过滤后为空直接 400「没有可执行的校验项，请先用『AI 生成校验项』生成后再保存」。
- 护栏：`test_create_rule_rejects_empty_checks`。

### D4（P2）AI 审校报的段落号会整体前移

- 现象：文档里夹空段时，AI 报的问题定位到错误的段落（界面「定位第 N 段」高亮错段，复检的匹配键也跟着错）。
- 根因：给模型的正文是按「非空行」重新编号的，而 `paragraph_index` 用的是含空段的真实下标。
- 修复：`_ai_check` 增加 `numbered_text` 入参，docx 场景传按真实下标编号的正文（并按 AI 预算截断）。
- 护栏：`test_ai_prompt_uses_real_paragraph_index`。

### D5（P2）撤销已确认的修改后，"已修正 ✓" 标记残留

- 修复：`undo_issue` 同时从 `resolved_ids` 摘掉该 id，回到"未处理"状态（界面上已复检的条目本来就不给撤销按钮，这里补的是接口层自洽）。
- 护栏：`test_undo_clears_resolved_flag`。

### D6/D7（P3）交互细节

- 没有待保存修改时点「保存修改」无任何反馈 → 改为提示「没有待保存的修改」。
- 客户端按 `skipped_reason=ai_only_record` 判断是否跳过复检，但服务端从不返回该字段（死分支）→ 改为按服务端已有的 `check_mode == "ai_only"` 给中性提示："该记录为纯 AI 校验模式（未配置格式规则），本次只重跑了 AI 内容审校"。

## 三、AI 生成是否成功（本次可验证与不可验证的边界）

已用 AI 桩 + 真实解析链路验证的部分：

| 场景 | 期望 | 实测 |
|---|---|---|
| 模型返回标准 JSON | 白名单过滤后回填表单 | ✅ 未知键被丢弃，中文"两端对齐"→`justify` |
| 模型返回带代码围栏 / 截断 / 中文引号的 JSON | 仍能解析 | ✅ `loads_lenient` 六道兜底（含截断修复） |
| 模型返回纯废话 | 明确报错、不落库 | ✅ 502「AI 这次返回的内容格式不规范…」 |
| 模型可用但描述无法映射 | 给出可照做的例子 | ✅ 400「例如：正文用仿宋三号字…」 |
| AI 服务不可用 | 明确报错 | ✅ 502/503，不会静默空返回 |
| 校验时 AI 审校与规则结果合并 | `check_mode=hybrid`、`ai_issue_count` 正确 | ✅ |

**未验证（需真机）**：本机连不上内网 14B（`/health` 不通），无法确认真实模型对「白话 → 校验项」提示词的实际命中率。
建议在桌面端点一次「AI 生成校验项」，判定标准：

- 正常：按钮下方出现"将按以下校验项检查"预览（如"字号：16 磅"），点保存成功。
- 异常：报"生成校验项失败：AI 这次返回的内容格式不规范"→ 服务端日志会有
  `规则校验项 AI 返回内容无法解析`，把原始输出贴回来即可针对性收紧提示词。

## 一、工作方式与硬性要求

这是一个持续迭代中的「白云司法局智慧办公平台」项目。

后续修改直接操作 GitHub 私有仓库 `liuwenyu599/agent` 的 `app` 分支。**用户已明确授权修改代码、提交代码，不需要每次再次询问是否允许。**

执行原则：

1. 直接读当前 `app` 最新 HEAD 后修改，不要依赖旧 blob SHA。
2. 修改完成后必须看 GitHub Actions 的 `Acceptance Gate`。
3. 如果 Gate 失败，只处理失败项，直到绿。
4. 当前项没有通过，不要贸然进入下一项。
5. 如果用户明确说「下面几项一起」，才允许批量做，但最后仍需统一 Gate。
6. 不要反复问已经明确过的问题，优先直接执行。
7. 用户偏好中文、技术化、简洁，不需要长篇解释操作过程。
8. **不要因为仓库任务切到 Work 模式**；当前工作一直通过 GitHub connector 直接执行。
9. 生产服务器部署和 GitHub 开发是两套事情，**不要在生产服务器随意做 git pull/push**。
10. **推送姿势**（本机 git 有严重怪癖，必须遵守）：
    ```bash
    # fetch
    GIT_SSH_COMMAND="ssh -i C:/GitSSH/idea_github -o IdentitiesOnly=yes \
      -o UserKnownHostsFile=C:/GitSSH/known_hosts -p 443" git fetch origin app
    # push
    GIT_SSH_COMMAND="ssh -i C:/GitSSH/idea_github -o IdentitiesOnly=yes \
      -o UserKnownHostsFile=C:/GitSSH/known_hosts -p 443" git push origin app
    # ⚠️ push 后 origin/app 必定不落盘，必须手写 ref：
    SHA=$(git rev-parse HEAD)
    mkdir -p .git/refs/remotes/origin && printf '%s\n' "$SHA" > .git/refs/remotes/origin/app
    ```
    验证：`git ls-remote origin app` 是权威对照。

## 六、模型服务

### 6.1 模型清单

| 端口 | 模型 | 用途 | 上下文 | 芯片 |
|---|---|---|---|---|
| 8002 | Qwen2.5-VL-7B-Instruct | 视觉（图片识别 / OCR） | 8192 | davinci2 |
| 8003 | Qwen2.5-14B-Instruct | 公文写作、知识库问答 | **16384** | davinci3 |
| 8004 | DeepPresenter-9B | PPT 生成 | **24576** | davinci4 |

### 6.2 关键启动参数

**14B（8003）**：
```
vllm serve /models/qwen14b
  --served-model-name Qwen2.5-14B-Instruct
  --host 0.0.0.0 --port 8001
  --dtype float16 --enforce-eager
  --max-model-len 16384
  --enable-prefix-caching
  --enable-auto-tool-choice
  --tool-call-parser hermes
```

**DP9B（8004）**：
```
vllm serve /models/dp9b
  --served-model-name DeepPresenter-9B
  --host 0.0.0.0 --port 8001
  --dtype float16 --enforce-eager
  --max-model-len 24576
  --enable-prefix-caching
  --enable-auto-tool-choice
  --tool-call-parser qwen3_xml
```

> **两个模型容器内端口都是 8001**，靠映射区分（14B→8003，DP9B→8004）。

### 6.3 310P 平台约束

- **只支持 FP16，不支持 BF16**（BF16 报 `DT_BFLOAT16 not implemented`）
- `--enforce-eager` **必须**（删不掉，代价是 decode 慢）
- **不支持多芯片 TP 跑大模型**（KV cache 会爆）
- 单芯片 43GB，KV cache "halved for workspace"（实际可用约一半）

### 6.4 context_folding 阈值坑

`window = CONTEXT_LENGTH_LIMIT(200000) // max_context_folds(5) = 40000`，远超 `--max-model-len 16384` → 阈值永不触发，撑到 16385 溢出。`max_context_folds` 同时是折叠次数上限，调到 18(@16384) / 12(@24576) 是"一石二鸟"。

## 七、PPTAgent 集成

### 7.1 两条独立链路

| 链路 | `convert_type` | 依赖模板 | 说明 |
|---|---|---|---|
| PPTAgent 模板路径 | `pptagent` | ✅ 需要 `templates/` | 模板填空 |
| **DeepPresenter 自由生成** | `deeppresenter` | ❌ 不需要模板 | 模型写 HTML/CSS，转 pptx |

**当前司法局走 `deeppresenter` 路径。**

### 7.2 Gradio 真实契约（权威，实机验证）

真身 **DeepPresenter 5.50.0（Gradio 5）**：

- 端点从 `GET /gradio_api/info` 拿
- 提交 `POST /gradio_api/call/send_message` → `{"event_id":...}`
- 消费 SSE `GET /gradio_api/call/send_message/{event_id}`
- **6 入参（顺序固定）**：`message` / `history` / `attachments` / `convert_type_value`("自由生成 (freeform)") / `template_value`("auto") / `num_pages_value`("auto")
- **5 出参**：`[3]` = 产物 pptx（FileData），`[4]` = Token 统计（**不是追问**）
- ⚠️ **Gradio 出参每元素包一层** `{"value":X,"__type__":"update"}`，产物在 `[3].value`，用 `unwrap_value()` 剥壳
- ⚠️ `PPT_AGENT_SUBMIT_PATH` 默认值是旧契约残留 `/api/ppt/generate` → **只配 URL 不配 SUBMIT_PATH 必 404**
- 耗时：受理 1.2s，1 页 ~100s，2 页 ~6 分钟。`PPT_AGENT_TOTAL_TIMEOUT=1800` **别调小**
- 没配 `PPT_AGENT_URL` = 走本地渲染（安全开关）

## 十、部署流程

### 10.1 打包（Windows）

**必须用 `git archive`**（不要 tar 整个目录）——只含入库文件，自动排除 `server/data`(56M)、`desktop/build`(463M)、`deploy/offline`(3.6G)，且不可能夹带 `.env`。

```bash
cd D:/Projects/judicial_app
SHA=$(git rev-parse --short HEAD)
git archive --format=tar --prefix=judicial_app_${SHA}/ HEAD -o .pkg/src.tar
```

**打包后必须处理两件事**（否则服务器上会出问题）：

1. **排除断链符号链接**：`training/data/raw` 指向实验室机器 `/home/lwy/datasets/agent`
   → 用 Python 遍历 `tarfile.getmembers()` 打包时 `continue` 跳过 `training/data/`
   > ⚠️ `tarfile.extractfile()` 处理 symlink 成员会抛 `KeyError: linkname not found`
2. **修可执行位**：`backup-production.sh` / `restore-drill.sh` / `install-backup-timer.sh` / `ascend-model-pool.sh` 在 git 里是 `100644` → 包内设为 `0755`
   > `deploy/pptagent/` 下 3 个无执行位是正常的：`probe_gradio_readonly.sh` 文档用 `bash xxx.sh` 调；`rebuild-images.sh` 生产禁用

### 10.2 上传与替换（服务器）

```bash
scp .pkg/judicial_app_XXX.tar.gz root@10.128.85.133:/tmp/    # 注意端口是 -P 大写
sha256sum /tmp/judicial_app_XXX.tar.gz

# 备份
TS=$(date +%Y%m%d_%H%M%S)
cp -r /opt/judicial_app /opt/judicial_app.prev-$TS

# 解压到新目录（不覆盖），核对后再整体替换
rm -rf /opt/judicial_app.new
mkdir -p /opt/judicial_app.new
tar xzf /tmp/judicial_app_XXX.tar.gz -C /opt/judicial_app.new --strip-components=1
```

## 十一、模型容器重建（不能用 docker commit）

### 11.1 为什么不能用 commit

vLLM 容器依赖 6 个 host bind mount 提供 NPU 运行时：
`/usr/local/dcmi`、`/usr/local/bin/npu-smi`、`/usr/local/Ascend/driver/lib64`、`/usr/local/Ascend/driver/version.info`、`/etc/ascend_install.info`、模型目录

**`docker commit` 不保存任何挂载** → 新镜像里 driver 目录是空的 → `import torch` 报 `RuntimeError: Failed to load the backend extension: torch_npu`。

### 11.2 正确做法：原始镜像 + 完整 run 命令

**14B**：
```bash
docker rm -f justice-qwen-14b
docker run -d --name justice-qwen-14b --restart unless-stopped --shm-size=8g \
  --device /dev/davinci3:/dev/davinci0 \
  --device /dev/davinci_manager --device /dev/devmm_svm --device /dev/hisi_hdc \
  -v /usr/local/dcmi:/usr/local/dcmi \
  -v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi \
  -v /usr/local/Ascend/driver/lib64:/usr/local/Ascend/driver/lib64 \
  -v /usr/local/Ascend/driver/version.info:/usr/local/Ascend/driver/version.info \
  -v /etc/ascend_install.info:/etc/ascend_install.info \
  -v /home/lcode/Qwen2.5-14B-Instruct:/models/qwen14b:ro \
  -e ASCEND_RT_VISIBLE_DEVICES=0 \
  -p 8003:8001 \
  m.daocloud.io/quay.io/ascend/vllm-ascend:v0.23.0-310p \
  vllm serve /models/qwen14b \
    --served-model-name Qwen2.5-14B-Instruct \
    --host 0.0.0.0 --port 8001 \
    --dtype float16 --enforce-eager --max-model-len 16384 \
    --enable-prefix-caching --enable-auto-tool-choice --tool-call-parser hermes
```

**DP9B**：同结构，改 `--device /dev/davinci4`、`-p 8004:8001`、模型路径 `/models/dp9b`、`--max-model-len 24576`、`--tool-call-parser qwen3_xml`。

**反推脚本**：`/opt/justice-office/deploy/run-<容器名>.sh`，由 `deploy/generate-run-scripts.py` 从 `docker inspect` 自动生成。

> ⚠️ 仓库 `deploy/docker-compose.model.yml` **缺 tool-call 参数**，按 compose 重建会丢 tool-call，改之前必须先补齐。
